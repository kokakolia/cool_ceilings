# Проверка входа по email-коду

Обновлено 24 ноября 2026 года. Прогон — 24 ноября 2026 года.

Итоговая сборка проверена в отдельном Compose `ceilings-login-final` с чистыми томами на Windows и Docker Desktop. Браузерные сценарии выполнены в Microsoft Edge с системным доверием к локальному HTTPS. Для тестов использованы отдельные учётные записи и локальный Mailpit.

| Проверка | Фактический результат |
|---|---|
| Вход и роли | Код пришёл через Auth → RabbitMQ → Noti → Mailpit. Клиент и админ вошли в браузере с одним email и разными назначениями кода. Клиент не получил доступ к панели. Повтор использованного кода и клиентский код в админском входе отклонены. |
| Сроки и лимиты кодов | Повтор до минуты и шестой выпуск за час получили `429`. После пяти неверных вводов правильный код отклонён. Проверка истёкшего кода отклонена, два одновременных подтверждения дали один успех. Для границ срока тест использовал заданные времена в тестовой БД. |
| Токены и вкладки | Обе cookie имели `Secure`, `HttpOnly`, `SameSite=Lax` и точный хост Web. После перезагрузки с подписанным истёкшим JWT две вкладки выполнили один refresh. После обмена с потерянным ответом повтор старого refresh token отозвал только его сессию. Другая сессия той же учётной записи продолжила обновляться. |
| `Origin` | Запрос и подтверждение кода, refresh и выход отклонили отсутствующий `Origin`, `null` и origin Mailpit с `403`. |
| Выход | При остановленном Auth браузер показал ошибку и сохранил обе cookie. При потере ответа после подтверждённого на сервере отзыва повтор вернул `204` и очистил cookie. Вторая вкладка ждала общего замка и после выхода не отправила старый refresh token. |
| Перезапуск Noti | Команда дождалась остановленного обработчика в RabbitMQ. После старта Mailpit получил письмо. SMTP `451` сохранил время повтора, остановка Noti после фиксации состояния не сбросила его, после запуска выполнена вторая попытка. |
| Неизвестный исход SMTP | SMTP отключён после приёма DATA. В отдельном прогоне Noti принудительно остановлен во время той же фазы. Обе команды завершились со статусом `unknown`, на SMTP зафиксировано по одной попытке. Сбои моделировались отдельным SMTP-сервером в тестовой сети Docker. |

Запрос на неизвестный административный адрес не создал код в Auth. При остановленном RabbitMQ запрос вернул признак неподтверждённой публикации в пределах бюджета времени. Noti удалил запись завершённой доставки старше срока хранения без поступления нового письма.

## Дополнительные прогоны 24 ноября

Проверено в `ceilings-login-idn-qa` на Windows в Edge и локальном Mailpit. Тестовый браузер был направлен на отдельный порт Compose с проверкой TLS.

- **Кириллический домен.** Клиент и админ вошли по кодам на адреса с доменом `пример.рф`. Mailpit получил домен в Punycode. Форма и команда создания админа отклонили Unicode до `@`. Отдельно проверены старые команды с Unicode в RabbitMQ. Команда с кириллическим доменом доставлена, а команда с Unicode до `@` завершилась как `failed` до вызова SMTP.
- **Потеря подтверждения RabbitMQ.** Тестовый Auth получил три кадра `Basic.Ack` от работающего брокера. Тест перехватил их до передачи результата издателю. Все публикации использовали один ID. После опустошения очереди в Mailpit было одно письмо, а в Noti записана одна завершённая попытка. Браузер показал предупреждение о неподтверждённой отправке, код из письма позволил войти.
- **Абсолютный срок сессии.** Для активных сессий клиента и админа в тестовой базе задано окончание через минуту. Браузеры обновили токены, `exp` обоих новых JWT совпал с сохранённым сроком сессии. Сроки в базе не сдвинулись. После фактического истечения Web вернул `401` и при запросе с новым JWT, и при попытке обновления с новым refresh token для каждой роли.

Испытания реального SMTP, выпуск первой заявки и письма о заказах относятся к следующим задачам. Координация вкладок проверена в Edge с Web Locks.

После приёмки тестовый Compose остановлен с сохранением его томов. Рабочий `ceilings-local` обновлён, обе страницы входа ответили `200`. Тестовая запись админа осталась в отдельном Compose. Для входа в рабочую панель сначала нужна персональная запись, созданная служебной командой из [инструкции](local-compose.md#запуск-с-нуля).
