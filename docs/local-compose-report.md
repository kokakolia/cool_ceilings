# Приёмка основы локального Compose

Обновлено 24 ноября 2026 года. Основной прогон — 23 ноября 2026 года.

Окружение — Windows (сборка 26300), Docker Desktop 4.99.0 с Linux-контейнерами, Docker Engine 29.9.3, Compose 5.7.0 и Microsoft Edge 158.0.4370.33. Проверочный проект `ceilings-foundation-qa` запускался с пустыми Docker-томами.

## Фактические результаты

| Проверка | Результат |
|---|---|
| Основа и миграции | Запустились Web, Auth, Order, Noti, три PostgreSQL, RabbitMQ, Mailpit, `step-ca` и три Envoy. Auth, Order и Noti подключились по TLS под `app_user` к собственным БД. Подтверждены ревизии `auth_001`, `order_001`, `noti_001`. |
| Первый админ | Команда создала одну тестовую запись в Auth. Повтор с тем же email вернул тот же ID. Запуск с другим email завершился отказом. В БД остался один админ. |
| HTTPS и неизвестный хост | Оба адреса вернули `200`, в чистом профиле Edge сертификат принят через системное доверие. Запрос к корректному TLS-имени с `Host: unknown.ceilings.test` вернул HTTP `421`. |
| Тестовая cookie | В `Set-Cookie` есть `Secure` и отсутствует `Domain`. Edge сохранил cookie и отправил её обратно на Web. В сетевом запросе документа Mailpit этой cookie нет. |
| Внутренние соединения | Web получил `200` от Auth и Order по mTLS. PostgreSQL отклонил подключение без TLS, драйвер отклонил сертификат с несовпадающим именем. Рабочая роль Auth не смогла создать таблицу. В сети Auth имена двух чужих БД не разрешились. RabbitMQ принял TLS 1.3 на AMQP-порту, обычный AMQP-порт закрыт. В брокере подтверждены отдельные права четырёх записей. |
| Ручное обслуживание | Выполнены `rekey` и загрузка сервисного и корневого CRL для всех трёх Envoy. Envoy не перезапускались, затем оба mTLS-вызова вернули `200`. После ручной замены сертификатов `pg-auth` и RabbitMQ на новых соединениях видны новые серийные номера. Первый админ и очереди сохранились. |

## Повторная проверка браузера 24 ноября

В основном прогоне имена были заданы в тестовом профиле Edge. При повторной проверке добавлены два имени в системный `hosts`. Поскольку в Windows включён ручной прокси, в его исключения добавлены `app.ceilings.test` и `mailpit.ceilings.test`. Свежий профиль Edge с обычными сетевыми настройками получил HTTPS `200` на обоих адресах без ошибок сертификата. Cookie Web отправилась на Web и отсутствовала в запросе к Mailpit. Порядок настройки описан в [инструкции](local-compose.md).

## Восстановление после простоя и раздельные пароли 24 ноября

- В `ceilings-foundation-qa` выпущены семь тестовых сертификатов на 48 секунд. Compose остановлен до их истечения. Обычный `up` распознал истечение, а ручной `recover` выпустил семь новых сертификатов и загрузил CRL. Web ответил по HTTPS, вызовы к Auth и Order через mTLS вернули `200`, три PostgreSQL прошли проверки готовности, RabbitMQ установил TLS 1.3. Имена и время создания всех 17 томов сохранились. У первого админа сохранился прежний ID.
- На чистом CA проверены запуск и выпуск сертификатов с раздельными паролями. На существующем CA заменён ключ оператора, ранее защищённый общим паролем. Паролем запуска CA новый ключ не расшифровывается. В контейнере `ca` есть только пароль запуска, процессу `pki-order` оба пароля недоступны. Оператор выпустил новые сертификаты, а обычный `rekey` действующего сертификата сохранился после перехода.

Разделение паролей применено и к рабочему `ceilings-local`. Сверка записей админов до и после обновления прошла. Web ответил по HTTPS, Compose оставлен запущенным.
